rapp-capability-interchange/1.0

A skill that can prove it still means what it meant.

Toasted Skills is an additive standard for SKILL.md. It gives a skill a canonical record, a drift oracle, and single-file agent portability — without changing one frontmatter field, and without migrating anything.

The question nothing can currently answer

Skills became production infrastructure without acquiring the safety properties production infrastructure has. A skill is prose; the systems it drives execute against real credentials. Agents are increasingly permitted to rewrite them.

“Does this capability mean today exactly what it meant when we approved it?”
Today that has no answer. You cannot attest to a control you cannot prove is unchanged.

Drift here never fails loudly. A drifted dependency crashes; a drifted skill keeps working and does the wrong thing confidently. It is found by its consequences, not by its errors.

Bread and toast

A hand-written SKILL.md is raw bread: prose with no canonical form. It cannot be tested for fidelity, because there is nothing to be faithful to — comparing two renders and asking whether they agree is not a test.

Toasting scans the prose, derives whatever deterministic layer is actually evidenced there, and freezes it as a record the file carries with it. Everything after that stake is measurable. Nothing before it is.

toaster.py toast  my-skill/SKILL.md   # derive + anchor; idempotent
toaster.py soak   my-skill/SKILL.md   # prove it does not drift

Derivation is conservative by rule: a parameter counts only if it appears inside a command the document actually gives. Inventing a contract the author never implied is drift with extra steps.

Three properties a round trip cannot see

Drift is an accumulation failure. Every hop looks plausible; twenty hops later the capability means something else and no commit is to blame.

Fixed point

After one normalising pass, repeated conversion must stop changing bytes.

Path independence

Every route must land on identical bytes. If the route changes the destination, the format is lying about being a projection.

Idempotence

Converting to a format twice in a row is a no-op.

A projection must never be mistakable for the thing it projects from.

Measured in the field

Against real corpora, not fixtures. Every number reproducible.

The oracle earned its place by catching a bug that every single round trip had passed: a projection re-emitted a platform-specific metadata key, so format detection reclassified it as the thing it was projecting from — and overwrote the original with a derived copy. 26 chains failed. One round trip never would have.

Counter-evidence, reported because the spec requires it

9 of those 50 skills yielded nothing machine-recoverable. Prose-heavy skills declare little that can be derived conservatively. That is a finding about the corpus — most skills in circulation carry almost no machine-recoverable contract — and it is the strongest argument for anchoring them, not against it.

Nothing migrates

The reflex when formats diverge is to converge them: pick a winner, write a migration tool, deprecate the rest. Nobody is going to migrate five thousand skills — and if they did, the next runtime would restart the problem.

A shim leaves every artifact exactly where it is, in exactly the format its platform wants, and makes the canonical record travel inside it. Formats stop being destinations you move between and become simultaneous projections of one thing.

A migration tool would never need byte-exact round-tripping. One-way conversions never come back. Fidelity has to hold in every direction, over unlimited hops, because this is a shim.
  • A toasted skill is a valid skill on every host that reads SKILL.md.
  • No frontmatter field is added, changed, or required — the capsule rides as an HTML comment.
  • Hosts that ignore it lose nothing they had.
  • A shim needs nobody's permission, so a registry can be toasted today by a consumer of it, without the registry changing anything.

What you get for free

Because the canonical record travels inside the artifact, any toasted skill also projects into a single self-contained file — stdlib only, no install, no framework — that declares a standard tool contract and runs anywhere:

python3 my_skill_agent.py --tool          # emit the JSON tool contract
python3 my_skill_agent.py '{"arg":"…"}'  # run it, deterministically

…and converts back to the original skill, byte for byte. The skill stays a skill. It is simply also portable, runnable, and provable.
